# Copias offline experimentales

Este paquete interno crea instantáneas SQLite independientes con `VACUUM INTO`, que incorpora el contenido del WAL, y escribe el manifiesto al final. Acepta estado obligatorio, almacén cifrado e intenciones opcionales. El manifiesto solo contiene nombres lógicos, tamaños y SHA-256; la identidad age debe guardarse separadamente. Restauración verifica manifiesto, hashes y `PRAGMA quick_check`, versiones y columnas principales según el papel de cada base antes de copiar a un directorio nuevo. Los hashes detectan corrupción accidental, no autentican la copia. La comprobación estructural no valida todas las restricciones del esquema ni descifra el vault; la identidad original y las comprobaciones de apertura de cada almacén siguen siendo necesarias.

La CLI offline `go run ./cmd/darsena-backup` se describe en `docs/operations.md`. Detener todos los procesos que puedan abrir los almacenes es un requisito: el bloqueo del worker solo impide otro usuario del mismo bloqueo; no protege procesos que abran directamente el vault o las intenciones, y el arranque actual abre el vault antes de adquirirlo. Las instantáneas de bases distintas no forman una transacción conjunta. Las comprobaciones de rutas no son atómicas frente a un proceso que modifique los directorios; estos deben ser privados y estar bajo control exclusivo del operador. Una copia cuyo manifiesto falta es incompleta. Si se pierde la identidad age original, este paquete no permite recuperar los datos cifrados.
