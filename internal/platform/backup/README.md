# Experimental offline backups

This internal package creates independent SQLite snapshots with `VACUUM INTO`, which incorporates the WAL contents, and writes the manifest last. It accepts mandatory state, the encrypted vault and optional intents. The manifest contains only logical names, sizes and SHA-256 hashes; the age identity must be stored separately. Restore verifies the manifest, hashes and `PRAGMA quick_check`, and the versions and main columns according to the role of each database, before copying to a new directory. The hashes detect accidental corruption; they do not authenticate the backup. The structural check does not validate every schema constraint or decrypt the vault; the original identity and the opening checks of each store are still required.

The offline CLI `go run ./cmd/darsena-backup` is described in `docs/operations.md`. Stopping every process that could open the stores is a requirement: the worker lock only prevents another user of the same lock; it does not protect processes that open the vault or the intents directly, and the current startup opens the vault before acquiring it. Snapshots of different databases do not form a joint transaction. Path checks are not atomic against a process that modifies the directories; these must be private and under the operator's exclusive control. A backup whose manifest is missing is incomplete. If the original age identity is lost, this package cannot recover the encrypted data.
