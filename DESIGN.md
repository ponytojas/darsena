# Dársena design

The agreed direction is a sober local utility: hierarchy through alignment, separators and system typography, with discreet surfaces and a selectable accent. Examples and definitions share a single list of applications; the type is an attribute, not a navigation section.

The main title uses 24 px, sections 15–16 px, controls 14 px, and metadata and logs at least 12 px. On mobile, fields use 16 px and touch targets at least 44 px. Light and dark modes are kept (dialogs dim the page with a `--scrim` veil that is stronger in dark mode), along with twelve square accents, visible focus and reduced-motion preferences. Existing components use shadcn/Base UI. The operation log is a compact grid (number, time and message on the same baseline, hanging indent when wrapping).

Emil, shadcn and Rauno are conceptual inspirations for craft and interaction, as requested; no external mockup or exact visual copy has been approved. The semantic success and error colors are independent of the accent. Lists use separators and discreet 4–6 px radii; the main spacing is 24–36 px. The interface keeps loading, empty, error and focus states; motion is functional and is removed with the reduced-motion preference.

## Navigation and structure

The sidebar has three destinations: Applications (with a counter), Activity and Diagnostics, and, when the worker is ready, a "Projects" section (color square, name, counter and "New project"); in the mini bar each project is its initial on the color, with a tooltip. On desktop it collapses to a 56 px mini bar (icons with tooltip and `aria-label`) with ⌘B / Ctrl+B, and the preference is kept; up to 600 px it is a transient menu. Settings opens from the sidebar footer and is organized in categories (Appearance: theme and accent; Language; Interface: show or hide the GitHub link, `darsena.githubLink`; System: link to Diagnostics) with a tabs pattern: vertical list on the left on desktop, scrollable horizontal tabs on mobile, arrows with activation on focus. Closing with Escape returns focus to the control. The ⌘K / Ctrl+K palette searches applications, routes and actions (new application, theme, language) with a combobox pattern and returns focus on close.

The Applications list is grouped: one group per project (header with an `aria-hidden` color square, alphabetical order according to the language), "No project" and "Examples"; empty groups are hidden. Rows of about 48 px with a status strip, name, monospaced subtitle, type, status and last change; on mobile they are compact cards. Filters by type and "Need attention", search with `/` and collapsible groups. Examples show their last 10 deployments in the row as colored dots (decorative and hidden on mobile) with an equivalent text for screen readers only. Each application has a detail page with linkable tabs (Summary and Deployments for examples; Summary, Variables, History and Settings for definitions) and a single "Next step" according to its state. An unsaved draft warns before leaving. Creation starts by choosing the type when there is more than one.

## Projects, selection and history

A project's page (`/projects/:id`) reuses the applications list with a bounded summary, "Edit" and "Delete"; the color is chosen with a group of square radios (a single tab stop, arrows, Home and End). Creating and editing use a dialog with inline validation and translated errors inside the dialog itself; a version conflict offers "Reload project". Deleting a project never deletes applications: they move to "No project" and the notice offers "Undo".

"Select" activates the list's selection mode: definitions become rows with a native checkbox (arrows, Home and End move focus, Space toggles, Escape exits) and examples are dimmed, without a checkbox and with a screen-reader-only text. The selection counts only what is visible. An action bar (sticky at the top on desktop, fixed at the bottom on mobile) shows the counter with `aria-live`, "Move to project…" and "Cancel"; an error is shown in the bar and keeps the selection.

The History tab lists configuration revisions, from the most recent to the oldest, with a relative date (the title shows the absolute one), the base revision marked and the changes as text with a lock for secrets. Values are never shown. "Restore previous value" opens a dialog explaining that a new revision is created and that the value is not shown; in experimental mode it adds that it does not modify the existing service. A conflict shows the translated message and "Refresh", without retrying.

The Settings tab groups project (saved on selection), image and port (explicit save with conflict detection; the image is locked with its explanation if the application had a service) and a danger zone. Deleting requires typing the name and, if the application had a service, is disabled with the reason visible. The unsaved draft is protected like the variables one.

## States and notices

The status vocabulary is single: ok, in progress (progress), attention (attention) and idle (idle). It is always shown with an icon and text, and as a colored strip (the "berth", *atraque*) on the edge of the row or the header; the strip is decorative and does not replace the text. The results of reversible or background actions are communicated with temporary notices (sonner, 10 s, with a close button, pause on mouse or focus, and a "Notifications" region reached with Alt+T); they offer "Undo" only when a real undo exists. There are few fixed notices: the mode pill (Demo / Experimental, with its availability) links to Diagnostics, and in demo a single line under the header reminds that deployments are simulated. The rest of the capability detail lives in Diagnostics, with a next step (copyable command or documentation) for each failed check.

Creation is a single action: "Deploy" (experimental) goes through checking the image, downloading it if missing, creating the project typed in "+ New project…", saving, saving variables, creating the service and waiting for its state, with a list of stages (icon and text, never color alone; polite `aria-live`); a failure says at which stage, that what was done is kept, and offers "Retry", which continues from there. "Save without deploying" stops at saving. Variables are optional rows (name, value, "Secret"; stacked on mobile) and the port lives under "More options". Access is chosen with an "Access" control inside "More options" (Isolated, Internal network or Open on this computer; Isolated by default). With `EXPOSE` in the image, Open is preselected with its port, without overriding a manual choice. Each level shows a note with what it implies; Open adds the warning that it has no authentication. The "Also connect to the common network" checkbox appears only with a network. The domain shows a preview of its address and an inline warning if it is already in use. "Open" in the detail links to `http://<domain>.localhost`, shows the application's internal name and reminds that there is no authentication. The image is shown as it was typed (`nginx:1.27`); the digest is secondary data in the detail. A live service is re-read every 5 s; if it ends on its own it is labeled "Exited" with its exit code. A definition's image field queries the server after a typing pause and shows, in a polite `aria-live` region under the help text, the canonical form that will be saved (and, if a tag was typed, that its current digest is pinned) and, in experimental mode, whether the runtime has it: downloaded (with platform), "It will be downloaded when deploying.", downloading or incompatible (platform or volumes, flagged before downloading according to the registry). A line is reserved while a result may arrive so that the controls below do not move under the pointer. A reference already pinned by digest can be saved without waiting for the check. The "Next step" of a definition without a service is "Deploy" (with the download included); with an incompatible image it offers "Change image".

## Language and brand

The interface is in Spanish and English. The language is chosen only in Settings, it always starts in Spanish and is saved like the theme and the accent; errors are translated by status and code, without showing server text. The brand is a symbol of piers (also the favicon) on the active accent.

Operational states use explicit text in addition to color: the header says when the server state is pending or unavailable, and saved applications distinguish worker, encrypted vault and real execution. On a disconnection, refreshing the state is offered, drafts are kept and dependent actions are disabled until their availability is confirmed.

In experimental mode, the owner's access precedes private actions. Creation shows the chosen access with its note before deploying; the observed state and the accepted revision are visible. Stopping and deleting are separate actions; deletion requires accessible confirmation and keeps the definition and configuration. On an uncertain result, checking is offered, without automatically repeating the action. Simulation screens remain separate from experimental mode.
